02 / Tree · commands

One role interface, three standalone entrypoints

The tree is proposed command grouping, not a final flag contract. A top-level update applies to the invoked binary.

Input
Role, quick-run flags or a separate run -c command; it selects a role while its/ita already select one.
Logic
Parse and validate arguments; dispatch to role use case; show complete help and consistent short options. TCP is the default. Quick run uses a temporary identity unless a key is explicitly supplied.
Failure / output
Invalid inputs fail with actionable help; quick run does not silently write configuration. Exact flags, error codes, and help wording are not yet finalized.

04 / Flowchart · config and identity

Configuration, migration and status

The migration branch below applies to legacy macOS config; the exact legacy path must be verified. New config always wins.

Config commands
Manage role configuration and identity: add/remove/list services, show/edit/path and key generation or rotation. Validate input; exact command names, secret presentation and rotation confirmation remain to be specified.
Default paths
macOS/Linux: ~/.config/iroh-tunnel and ~/.local/state/iroh-tunnel, ignoring XDG variables. Windows: LocalAppData/iroh-tunnel/config and .../state. Explicit application overrides remain available.
Migration / errors
If new config exists, do not inspect old config. Otherwise copy legacy config without overwrite or deletion, protect secret permissions, and stop on copy error rather than generating a replacement identity. First-time setup when neither exists remains to be specified.
Status / ownership
Role runtime writes status; status command reads the selected scope. Refuse a second instance of the same role (system service, or same-user modes); ownership and locking implementation remain open.
05 / Flowchart · service management

Install with explicit scope and pinned paths

Trigger / input
service install for a role, selected configuration and associated user state path. User scope versus system scope is distinct from binary installation scope.
Decision
Non-elevated users choose scope; --system selects system. If system privileges are missing, stop and instruct rerun with sudo on Unix or an elevated Administrator terminal on Windows. Never elevate or fall back automatically. Root/elevated Administrator defaults to system without a scope prompt.
Install
Resolve and pin absolute config/state paths of the relevant user. If an existing system service points to another user, confirm before changing the service; retain both users' config files. Unknown invoking user: select interactively, or fail with guidance when non-interactive.
Operations
Start, stop, status and uninstall target the selected role and scope. A service must have permission to read the key/config and write status; failure stops with guidance, without silently widening permissions.

Security / open
Privileged services reading user-editable config cross a trust boundary; account, ownership, file integrity and symlink validation need design. Windows login-session background mechanism is deferred. See service boundary and OS adapters.
06 / Swimlane · release and operation

Separate publisher, operator and installation owner

Release
CI signs release using keyless identity; publish checksums and independently packaged it, its and ita, plus three images. Trust identity pinning and rotation details require design.
Installer
install.sh and install.ps1 install all three by default, system-wide by default. Confirm PATH changes and collisions before replacing existing files.
Self-update
Each binary updates itself independently, stable latest by default or an explicitly selected version. Verify signature and checksum before replacing; verification failure preserves the old binary. Explicit unsafe bypass warns; checksum-bypass details remain open.
Update paths
Install ownerUpdate path
StandaloneVerify selected binary; request consent or guide restart when running; replace.
Package managerDelegate to the package for the corresponding binary.
ContainerInstruct pull and redeploy; do not self-update in container.
Ownership / failure
Package-managed binaries delegate to their own package manager; old bundled packages require migration. Containers update by pulling a new image and redeploying. Do not silently interrupt active tunnels; seek confirmation or give stop/restart guidance. Atomicity and rollback remain open.
07 / State machine · proposed runtime

Runtime lifecycle boundaries

Proposed state model; bounded retry and drain are confirmed, while numeric defaults and detailed recovery mechanics remain open.

Invalid config, failed migration or conflicting ownership fail before Running. The exact state machine, cleanup and recovery policy are design proposals, not an established runtime contract.
