### Issues

**WARNING**
- **W1** "Elevated user installs with defaults" (no `--config`) is covered only by the unit test `system_windows.rs` `defaults_use_token_user_paths`. Recommendation: add an E2E that installs without `--config` after `config keygen` in the runner's real `%LOCALAPPDATA%`, with a guard that removes the generated config.
- **W2** "Slow stop" is covered only by unit tests with an injected probe; there is no live slow-stop E2E. Recommendation: add an E2E that holds the role lock from a helper process across `restart --system` and asserts the service error and that no second instance starts.
- **W3** The "Service stop request" and "SIGTERM" scenarios specify a log line. The drain is proven, but the text is not asserted. Recommendation: in `stop_pending_reported_while_draining`, assert that `serve.log` contains `received service stop request`.

**SUGGESTION**
- **S1** A non-elevated run refuses a user-pre-created weak `%ProgramData%\iroh-tunnel` (exit 3) for every user until an admin removes it. This follows the spec, but it is a local denial of service. Recommendation: owner decision. Either skip verification on the read-only shared side, or document the behaviour in `docs/troubleshooting.md`.
- **S2** TOML syntax errors exit 1, not 2. This affects all platforms and predates the change. Recommendation: map `ConfigDoc::from_toml` parse errors to `CliError::Config` in a separate change.
- **S3** Run a focused `security-auditor` pass on `trust_windows/model.rs` and `ace.rs` before release. The final review seat did not cover these files; each passed its task review.
- **S4** The test-quality minors listed in apply.md: `acl_state` fingerprint versus full SDDL, unasserted diagnostic details, the restricted-token helper caveats, `-BinDir` normalisation, and `CappedLog` reopen re-verification.
