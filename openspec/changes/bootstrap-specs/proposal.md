## Why

The existing iroh-tunnel implementation has source, tests and operator documentation but no living OpenSpec capability baseline. Drafting evidence-linked requirements makes current behavior reviewable before future changes, while explicitly distinguishing code-only inferences from behavior stated in tests or documentation.

## What Changes

- Add draft delta specs for 11 confirmed capabilities, including platform-specific paths within `tunnel-configuration`.
- Record observable behavior with evidence and WHEN/THEN scenarios; label code-only requirements `Confidence: inferred`.
- Add the capability map and documentation-only design stub in this change.
- Keep drafts out of `openspec/specs/` until the normal review and completion flow authorizes synchronization.

No product code changes; tasks verify each spec against the code and its evidence.

## Capabilities

### New Capabilities

These names introduce specification coverage for existing behavior, not new product features.

- `cli-entrypoints`: Executable surfaces, command parsing, quick mode and role dispatch.
- `tcp-tunnel-forwarding`: TCP forwarding, multiplexed channels, reconnects and failure isolation.
- `udp-datagram-forwarding`: Experimental UDP datagram transport, flow lifecycle and resource limits.
- `iroh-endpoint-relay`: Endpoint identity, relay selection, authentication and self-hosted relay operation.
- `tunnel-configuration`: TOML defaults, validation and platform-specific config/state paths.
- `config-management-commands`: Configuration editing, key generation and safe persistence.
- `connection-path-status`: Role status snapshots, status display and connection-path diagnostics.
- `role-ownership-shutdown`: Single-owner role execution and graceful/forced shutdown behavior.
- `system-service-management`: Platform-specific service lifecycle, scope, accounts and installation trust.
- `self-update`: Release selection, verification, replacement and installation ownership handling.
- `install-release-packaging`: Installers, release artifacts, packages, containers and distribution checks.

### Modified Capabilities

None. No existing spec directory matched the confirmed candidates.

## Impact

Only files under `openspec/changes/bootstrap-specs/` are generated by this change. Source evidence covers `src/` (including `src/service/`), `tests/`, relevant `docs/`, `examples/`, `packaging/`, `.github/workflows/`, root installers, Docker files and `build.rs`. No source code, API, CLI behavior, dependency, schema or runtime data is changed.

Excluded scan directories are `openspec/`, `.git/`, `node_modules/`, `dist/`, `build/`, `vendor/`, `target/` and generated files. Validation checks document structure; tests and E2E behavior are not rerun as part of drafting. Review the specs, then run `/opsx-ff bootstrap-specs` in the isolated worktree to continue the normal artifact flow.
